# Implementation roadmap

Phase 0 defines contracts only. **Do not start Phase 1 without a separate instruction.** Gates below are ordered by technical dependency; optional inspection follows the core engine rather than blocking it.

| Phase | Objective and scope | Dependencies | Deliverables | Tests, acceptance and exit condition |
| --- | --- | --- | --- | --- |
| **0 — Architecture and contracts** | Research browser C toolchains; settle provisional ABI, API, lifecycle, security, limits and distribution. No implementation. | Repository inspection and primary-source research. | This documentation set, README, pending-license notice, review. | Cross-document consistency and source audit. Exit with `COMPLETE WITH OPEN DECISIONS` only if browser feasibility is supported by evidence and open integration gates are explicit. |
| **1 — Browser feasibility** | Pin browsercc/Clang/LLD/sysroot and WASI host candidates. In an isolated local browser harness, prove one-file C17, headers, stdin/stdout/exit, diagnostics, two-file link, and Worker termination. Record imports/features, asset bytes, timings and licenses. This is disposable research code, not the public engine. | Phase 0. | Feasibility report, pinned manifest draft, go/no-go toolchain decision. | Real browser matrix smoke test. Exit only if all core proofs pass; otherwise try the documented fallback and revise Phase 0 decisions before API work. |
| **2 — Core API and validation** | Implement manager facade, portable schemas, request/path validation, immutable limits, state machine and fake adapters. | Phase 1 ABI confirmed. | `CEngine` skeleton, error/result types, protocol version. | Unit contract tests for invalid requests, concurrent calls, reset/dispose and stale messages. Exit when API agrees with docs and fake adapters pass. |
| **3 — Asset and compiler runtime** | Build/pin compiler Worker, asset manifest loading, sysroot mount, compiler adapter and handshake. No user execution yet. | Phases 1–2. | Reproducible asset loader and compiler Worker. | Cold/warm init, hash/version mismatch, stalled asset, Worker crash. Exit when initialization and recovery are dependable in real browsers. |
| **4 — Compilation and linking** | Compile every `.c` to an object, resolve headers and link to a P1 command; enforce artifact budget. | Phase 3 and Phase 1 multi-file proof. | `compile()`, opaque artifact store. | C corpus, headers, warnings, syntax/type/link errors, malformed options. Exit when full multi-file contract works. |
| **5 — WASI execution** | Implement disposable execution Worker, curated P1 imports, stdin/EOF, output sinks, exit/trap normalization; wire `execute()` and `run()`. | Phase 4 artifact output and P1 import proof. | Execution adapter and public result flow. | stdout/stderr, stdin, normal/nonzero exit, trap, repeat artifact, run compile failure. Exit when no engine fault is reported as a program exit. |
| **6 — Diagnostics** | Parse actual pinned Clang/LLD output conservatively, preserve bounded raw text and include context. | Phase 4. | Normalizer. | Warning/error/note/link fixtures and real compiler checks. Exit when location/severity are accurate where available and unknown lines do not fabricate data. |
| **7 — Cancellation, recovery and limits** | Add manager-owned deadlines, Worker retirement/recreation, generation checks, byte and artifact budgets. | Phases 3–6. | Hardened lifecycle and centralized limit enforcement. | Loop, flood, cancellation, reset, timeout, Worker crash and stale reply cycles. Exit when later runs recover or enter explicit `failed`. |
| **8 — Security boundary** | Implement and test separate-origin iframe bridge for hardened mode; apply CSP and message validation; audit guest imports and filesystem. | Phase 7 and host integration support. | Hardened deployment guide and bridge, threat-model test results. | Browser origin/storage/network/CSP tests. Exit when security claims match observed behavior; do not ship hardened claim if this gate fails. |
| **9 — Packaging and independent consumer** | Emit ESM package, Workers, hash-named assets, manifest and third-party notices; test in clean external project. | Phases 3–8. | Packable browser distribution and consumer example. | Clean build, asset hash audit, independent browser consumer, no dev path dependencies. Exit when install/copy/init/run works outside repository. |
| **10 — Optional inspection** | Add only proven preprocessing/IR/AST/assembly views behind explicit method and separate limits. | Core engine stable; user demand and feature proof. | Optional API/docs, if chosen. | Format and cap tests. Exit independently; this phase does not block core release. |
| **11 — Release readiness** | Final browser compatibility, dependency/license/source, security and performance audit; choose project license with owner; version public API and assets. | Core phases 1–9; phase 10 optional. | Release report and versioned artifacts. | Supported-browser matrix, notice review, packed archive verification, adverse workload retests. Exit only after all release gates and owner authorization for publication. |

The sequence moves proof of multi-file linking and Worker termination to Phase 1 because they determine whether the selected distribution can support the promised contract. Diagnostics implementation follows a working compiler; its raw-output capture must already exist in Phase 4. Security validation starts in Phase 1 and culminates before packaging. Tests are part of every phase, not a late standalone phase. Phase 11 covers final audits, not automatic publication.
